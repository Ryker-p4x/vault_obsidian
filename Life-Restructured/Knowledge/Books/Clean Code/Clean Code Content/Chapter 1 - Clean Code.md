It explains to us how bad code has destroyed companies and when there's bad code in a company a tiger team is hired, which is a bunch of new devs that'll try to remake the bad code but as clean code. (This process can take up to 10 years and the author claims to have seen it happen before)

It remarks that **clean code** makes it seem like the dev behind it put care and effort into it just like how you'd put effort into making a pie for example.

Bad code can slow you down heavily on making updates and making it much harder to push out any.

The author gives advice on if we were to improve one small part about our code each day to make it *cleaner* it would be incredibly hard for it to turn into bad code.

Conclusion: We must make clean code since it's a matter of survival for companies and for maintaining the code making sure you can push out updates quickly.
